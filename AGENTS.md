# ScholarFlow AI — Agent Constitution & Rules

This document outlines the constitution, boundaries, inputs, outputs, and design rules for each specialized AI agent operating within the ScholarFlow AI workflow pipeline.

---

## General AI Agent Principles

1. **No Hallucination**: Agents must only act on verified input fields present in the database or document OCR text. They are strictly prohibited from inferring missing critical details (like income values or GPA numbers).
2. **Structured JSON Output**: All agents communicating with the LLM must enforce JSON output format (`responseMimeType: 'application/json'`) to ensure type-safe parsing and API stability.
3. **Graceful Fallbacks**: If the AI model times out or the Gemini API key is missing, agents must trigger deterministic rule-based algorithms to compute outputs, ensuring 100% platform uptime.
4. **Audit Traceability**: Every decision, reasoning summary, and confidence score generated by an agent must be stored in the database (`AgentResult` and `AuditLog` tables) for manual inspection by officers.

---

## 1. Document Verification & OCR Agent

* **Responsibility**: Perform document analysis, verify clarity, and extract structured fields.
* **Boundaries**: Reject files with non-matching names or invalid registration details.
* **Input**: Document file path, document type, student details, application fields.
* **Rules**:
  - Extract the student's name, identification numbers, and values.
  - Compare extracted document details with application form inputs.
  - If names differ significantly (e.g., mismatch of more than first/last order), set status to `REJECTED`.
  - Enforce Aadhaar digit validation (exactly 12 digits).

---

## 2. Eligibility Agent

* **Responsibility**: Apply scholarship rules to student profile parameters.
* **Boundaries**: Strictly evaluate limits; do not make exceptions.
* **Input**: CGPA, annual income, social category, scholarship rules.
* **Rules**:
  - Compare GPA: Must be greater than or equal to `criteriaMinCgpa`.
  - Compare Family Income: Must be less than or equal to `criteriaMaxIncome`.
  - Compare Social Category: Match caste criteria or verify general clearance rules.
  - Return detailed reasoning checklist showing PASS/FAIL status for each parameter.

---

## 3. Fraud Detection Agent

* **Responsibility**: Identify double-dipping, identity theft, or certificate reuse.
* **Boundaries**: Scan database scope; do not query third-party public registries.
* **Input**: Current applicant UID, bank identifiers, historic application logs.
* **Rules**:
  - Search other active applications for matching Aadhaar numbers.
  - Search other active applications for matching bank account numbers under different names.
  - Calculate a risk score (0.0 to 1.0) based on duplicate fields discovered.
  - Flag applications with risk scores >= 0.6 as `FAILED` (High Risk).

---

## 4. Officer Copilot Agent

* **Responsibility**: Summarize all automated audits and compile officer summaries.
* **Boundaries**: Do not final-approve or final-reject applications. Decision authority belongs solely to human officers.
* **Input**: Aggregated outputs from Document, Eligibility, and Fraud agents.
* **Rules**:
  - Provide a concise 2-sentence executive summary of the student's eligibility profile.
  - Highlight any warning flags or verification failures.
  - Recommend a decision (`APPROVE`, `REJECT`, or `REQUEST_REVISION`) to assist the officer.
  - Cite details supporting the recommendation.

---

## 5. Notification Agent

* **Responsibility**: Alert applicants regarding lifecycle status transitions.
* **Boundaries**: Direct email/SMS triggers; do not alter database application states.
* **Input**: Recipient user profile, application progress logs, event markers.
* **Rules**:
  - Format messages clearly without jargon.
  - Include comments added by human officers in revision requests.
  - Maintain logs of all dispatched messages in the database.
